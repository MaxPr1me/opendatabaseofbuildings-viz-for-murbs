3. METHODOLOGY
======================================================================

3.1 Data Ingestion
------------------
• Recursive GeoPackage discovery under data/ directory
• SQLite-based metadata inspection (no full data load for inventory)
• pyogrio for CRS and schema verification
• Field completeness calculated per-province via SQL COUNT queries

3.2 Geometry Metrics
--------------------
All calculations performed in EPSG:3347 (projected, metric units).

Metrics computed:
  • Footprint area (m²): polygon.area
  • Perimeter (m): polygon.length
  • Minimum Rotated Rectangle (MRR): shapely minimum_rotated_rectangle
  • Dimensions: major/minor axis of MRR
  • Aspect ratio: MRR_length / MRR_width (always >= 1)
  • Orientation: azimuth of major axis from north [0°, 180°)
  • Compactness (Polsby-Popper): 4*pi * area / perimeter^2
  • Rectangularity: area / MRR_area
  • Convexity: area / convex_hull_area
  • Holes: count and area of interior rings
  • Components: count of disconnected polygon parts

3.3 MURB Classification
-----------------------
Evidence-based classification with priority-ordered rules:

  R001: Explicit apartment/multi-residential type → confirmed_murb (1.0)
  R002: Dwelling units >= 4 → high_confidence_murb (0.85)
  R003: Floors >= 4 AND area >= 400 m² → probable_murb (0.70)
  R004: Area >= 600 m² AND residential type → possible_murb (0.50)
  R005: Height >= 12 m → possible_murb (0.45)
  R010: Explicit non-MURB type → non_murb (0.0)
  R011: Footprint < 200 m² → non_murb (0.0)
  R999: No matching rule → insufficient_information (null)

Minimum MURB unit threshold: 4 dwelling units (configurable)

3.4 Archetype Generation
------------------------
Method: K-means clustering with medoid selection
Features: footprint_area_m2, aspect_ratio, compactness, rectangularity
Preprocessing: StandardScaler normalization
Number of clusters: 6 (configurable)
Random seed: 42 (reproducible)

The medoid (most central actual building) is selected as the
representative for each cluster — NOT an averaged polygon.

3.5 gbXML Export
----------------
Intermediate building geometry model exported to gbXML 7.03:
  • Rectangular extrusion from MRR dimensions
  • Storey-by-storey surface generation
  • Proper surface types (ExteriorWall, Roof, UndergroundSlab)
  • Floor-to-floor height: 3.0 m (configurable)
  • WWR by orientation: N=0.30, E=0.30, S=0.40, W=0.30 (assumed)

5. LIMITATIONS
======================================================================
1. FOOTPRINT ≠ FLOOR PLATE: Ground-level footprints may include podiums,
   garages, and additions that differ from typical upper-floor plates.

2. NO WINDOW DATA: WWR values are archetypal assumptions, not observed.

3. GEOGRAPHIC BIAS: Only NS has sufficient unit-count data for direct MURB
   identification. National MURB statistics are dominated by data-rich regions.

4. SAMPLING LIMITATIONS: The national geometry metrics use 500 records per
   file from the beginning of each file, which may not be representative
   of the full provincial dataset.

5. CLASSIFICATION COVERAGE: Random sampling finds almost no MURBs (1/7500)
   because apartments are a tiny fraction of all buildings. Targeted SQL
   queries on attribute-rich records are necessary.

6. SINGLE-PROVINCE ARCHETYPES: The 6 archetypes are derived from NS only.
   National archetypes require multi-province MURB identification first.

7. STOREY ASSUMPTIONS: Floor-to-floor height (3.0 m) and storey count are
   assumptions for most buildings. Only 0–9% have observed floor counts.
